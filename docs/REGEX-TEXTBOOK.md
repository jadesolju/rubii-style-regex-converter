# ตำรา Regex: อ่าน เขียน ทดสอบ และนำไปใช้

ตำรานี้เป็นเนื้อหาอ้างอิงสำหรับคนที่อยากเข้าใจ Regex เพิ่ม ผู้ใช้ Client ที่ต้องการสร้างหน้าตา Rubii เริ่มจาก [Prompt Converter](../SkillPrompt.MD) ได้เลย ซึ่งพาเดินทีละขั้นโดยไม่บังคับให้เรียน Regex ก่อน ส่วนนักพัฒนาสามารถใช้บทเรียนเดียวกันผ่าน API ได้ เนื้อหาและตัวอย่าง Rubii สรุปใหม่จากเอกสารที่อ้างท้ายบท ไม่ใช่ข้อกำหนด API อย่างเป็นทางการของ Rubii

ถ้าต้องการให้ AI ช่วยคิด Regex ตามโจทย์ ให้คัดลอก [SkillPrompt.MD](../SkillPrompt.MD) ไปวางใน GPT, Gemini หรือ Claude แล้วกรอกตัวอย่างของคุณ

## 1. Regex คืออะไร

Regular Expression หรือ Regex คือรูปแบบที่ใช้บรรยายข้อความเพื่อให้โปรแกรมค้นหา ตรวจสอบ ดึงบางส่วน หรือแทนที่ข้อความได้ ตัวอย่างเช่น เราอาจต้องการหาบรรทัดที่เขียน `Affection: 72` แล้วเก็บเฉพาะค่า `72`

Regex มองเห็นลำดับตัวอักษร ไม่ได้เข้าใจความหมายของมันเอง Pattern ที่จับตัวเลขได้อาจจับอายุ คะแนน หรือวันที่ได้เหมือนกัน จึงต้องกำหนดว่าอะไรควรตรง อะไรไม่ควรตรง และตรวจตัวอย่างจริงก่อนใช้

## 2. Pattern, flags และ replacement

Regex ที่นำไปใช้มักมีสามค่าแยกกัน:

- **Pattern** คือกฎค้นหา เช่น `Affection[:：]\s*(\d{1,3})`
- **Flags** เปลี่ยนวิธีค้นหา เช่น `g` ให้ค้นหาต่อทุกตำแหน่งที่ตรง และ `i` ให้ไม่แยกตัวพิมพ์เล็กกับใหญ่
- **Replacement** คือข้อความใหม่ที่ใส่แทน match เช่น `Affection: $1` หรือเว้นว่างเพื่อลบส่วนที่ตรงออก

ใน JavaScript อาจเขียน Regex literal เป็น `/pattern/flags` แต่เมื่อหน้าตั้งค่าหรือ API แยกช่อง Pattern กับ Flags ให้นำค่าใส่คนละช่อง อย่าเติม slash ครอบเอง

ในไฟล์ JSON backslash ต้อง escape อีกชั้น เช่น `\d` ใน Pattern จะเขียนเป็น `\\d` ใน JSON source และหลัง parse จะกลับเป็น `\d` ตัวอย่าง request จริงดูได้ในบทสำหรับนักพัฒนา

## 3. อ่าน Pattern ตัวอย่างทีละส่วน

Pattern นี้ค้นหา label, เครื่องหมายโคลอน, ช่องว่างที่อาจมี และตัวเลขหนึ่งถึงสามหลัก:

```regex
Affection[:：]\s*(\d{1,3})
```

- `Affection` ต้องมีคำนี้ตามตัวอักษร
- `[:：]` ยอมรับเครื่องหมายโคลอนแบบ ASCII `:` หรือแบบ full-width `：` จำนวนหนึ่งตัว
- `\s*` ยอมรับช่องว่างศูนย์ตัวขึ้นไป
- `(\d{1,3})` จับตัวเลขหนึ่งถึงสามหลักไว้ในกลุ่มจับหมายเลข 1
- `\d` หมายถึงตัวเลข, `*` หมายถึงศูนย์ครั้งขึ้นไป และ `{1,3}` หมายถึงหนึ่งถึงสามครั้ง

ถ้าข้อความคือ `Affection： 72` ข้อความที่ match ทั้งก้อนคือ `Affection： 72` ส่วนค่าของ `$1` คือ `72` การจำกัดจำนวนหลักช่วยกันจับตัวเลขยาวโดยไม่ตั้งใจ แต่ไม่ได้ตรวจว่าค่านั้นอยู่ในช่วงคะแนนที่ต้องการ

เครื่องหมายพื้นฐานอื่นที่พบบ่อยคือ `+` (หนึ่งครั้งขึ้นไป), `?` (ศูนย์หรือหนึ่งครั้ง), `.` (อักขระหนึ่งตัวโดยทั่วไป), `^` (ตำแหน่งต้นข้อความ/บรรทัด) และ `$` (ตำแหน่งท้ายข้อความ/บรรทัด) ความหมายบางอย่างขึ้นอยู่กับ flags และ engine ที่ใช้

## 4. กลุ่มจับและข้อความแทนที่

วงเล็บจับค่าที่ต้องการเก็บจากข้อความ กลุ่มแรกเรียก `$1`, กลุ่มที่สอง `$2` ตามลำดับวงเล็บเปิด ตัวอย่าง Pattern ด้านบนมีวงเล็บจับเพียงชุดเดียว ดังนั้น Replacement `Affection: $1` จะคงค่าตัวเลขไว้แต่เปลี่ยนรูปแบบ label

`$&` อ้างถึง match ทั้งก้อนใน replacement ของ JavaScript; Rubii อธิบายการใช้ `$1` และ `$&` สำหรับกฎของตน ส่วน replacement syntax อาจต่างกันตามเครื่องมือ ควรใช้ตัวแปรที่เอกสารปลายทางระบุเท่านั้น ถ้า Replacement ว่าง ข้อความที่ match จะถูกลบ

อย่าสับสนระหว่าง Pattern กับ Replacement: `\d` เป็น syntax สำหรับค้นหาใน Pattern ขณะที่ `$1` ใช้อ้างกลุ่มจับใน Replacement

## 5. ใช้ Regex กับ Rubii

เมื่อสร้างกฎ ให้ตรวจชื่อและตำแหน่งของช่องในแอปก่อน แล้วคัดลอกค่าจากสูตรให้ตรงช่อง โดยทั่วไปควรบันทึกสิ่งเหล่านี้ไว้กับแต่ละกฎ:

- **Name:** ชื่อที่ช่วยจำหน้าที่ เช่น `Normalize Affection label`
- **Apply to:** กฎใช้กับข้อความทั้งหมด ผู้ใช้ หรือตัวละคร ตามตัวเลือกที่แอปแสดง
- **Matches in:** เลือก `Raw content` หากต้องเห็น Markdown/HTML หรือ marker ดิบ เลือก `Displayed text` หากต้องการเปลี่ยนข้อความที่แสดงหลังจัดรูปแบบ
- **Expression / Pattern และ Flags:** ใส่ค่าตามรูปแบบช่องของแอป
- **Replacement:** ใส่ผลลัพธ์ที่ต้องการ รวมทั้ง `$1` เมื่อจะคงค่าจากกลุ่มจับ; เว้นว่างเมื่อเจตนาคือลบข้อความที่ match

ตามบทความ Rubii, Regex ที่เลือก `Raw content` ทำงานก่อน Style tag expansion และ Markdown ส่วน `Displayed text` ทำงานหลังจัดรูปแบบ และกฎภายในขั้นทำงานตามลำดับรายการ ข้อความที่ถูกแบ่งเป็นหลายช่วง HTML อาจไม่ match ข้ามรอยแบ่งใน displayed-text stage

ลำดับภาพรวมที่บทความอธิบายคือ `Raw-content Regex → Style tags/Markdown → Displayed-text Regex → Global CSS` ถ้ากฎไม่ทำงาน ให้ตรวจว่าข้อความที่กฎมองเห็นอยู่ใน stage ที่เลือก และกฎอื่นก่อนหน้าเปลี่ยนข้อความนั้นไปแล้วหรือไม่

## 6. ปรับและทดสอบอย่างปลอดภัย

ก่อนแก้ Pattern ให้เขียนตัวอย่างสั้น ๆ สามกลุ่ม: ข้อความที่ต้อง match, ข้อความที่ต้องไม่ match และกรณีขอบ เช่น ไม่มีช่องว่าง มีช่องว่างหลายตัว label คนละชื่อ ค่าว่าง หรือจำนวนหลักเกินขอบเขต จากนั้นดูทั้ง match เต็ม, กลุ่มจับ และผล replacement

ปรับครั้งละจุด ถ้าชื่อ field เปลี่ยนให้แก้ literal; ถ้าความยาวค่าเปลี่ยนให้แก้ quantifier; ถ้าจำเป็นต้องอยู่ต้นบรรทัดจึงค่อยพิจารณา anchor อย่าทำ Pattern กว้างเพื่อให้ผ่านตัวอย่างเดียว

สำหรับ Rubii ให้ใช้ Preview ของ Rubii ก่อนบันทึกจริง การรัน JavaScript RegExp ยืนยันได้เฉพาะพฤติกรรมของ engine ที่รัน และไม่ได้จำลองการ render, HTML sanitization หรือขอบเขต text node ของ Rubii

## 7. เลือกเส้นทางสำหรับผู้ใช้แอปหรือนักพัฒนา

**ผู้ใช้แอปทั่วไป:** อ่านคำอธิบาย Pattern ที่เตรียมไว้ เลือกกฎที่ตรงเป้าหมาย คัดลอกค่าไปทีละช่อง ตรวจ stage และ Apply to แล้วลอง Preview ไม่จำเป็นต้องเปิด API หรือเขียนโค้ด ถ้าต้องการดัดแปลงจากภาษาธรรมดา ใช้ [prompt สำหรับ AI](../SkillPrompt.MD) พร้อมตัวอย่างข้อความสมมติ

**นักพัฒนา:** เรียกบทเรียนเป็น JSON ได้โดยเลือก `audience=developer` หรือ `audience=app_user` รับ Pattern จาก `/v1/patterns` และทดลอง JS RegExp ด้วย `POST /v1/regex/test` ตัวอย่าง:

```http
GET /v1/lessons?audience=developer
```

```json
{
  "pattern": "Affection[:：]\\s*(\\d{1,3})",
  "flags": "gi",
  "replacement": "Affection: $1",
  "input": "Affection: 72"
}
```

```sh
curl -X POST http://127.0.0.1:3000/v1/regex/test \
  -H "content-type: application/json" \
  --data '{"pattern":"Affection[:：]\\s*(\\d{1,3})","flags":"gi","replacement":"Affection: $1","input":"Affection: 72"}'
```

API รุ่นนี้เป็นบริการทดลองในเครื่อง ไม่มี API key หรือการควบคุมโควตาสำหรับผู้ใช้ภายนอก และ Regex engine คือ JavaScript RegExp ของ Node.js คำตอบ API จึงไม่ยืนยันผลบน Rubii, Python, PCRE หรือ engine อื่น
